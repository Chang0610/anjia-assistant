# 移居上海就业 AI 助手

本地网页底部提供“问答”“计划”“我的”三个入口。后端读取上海区域数据与已核验的核心政策事实，调用 OpenAI Responses API 生成回答、结构化日程提议，并从用户最新输入中整理长期资料。聊天产生的日程修改先显示完整确认表，只有用户点击确认才写入本机浏览器的计划日历；后续可继续通过聊天增删改，或在日历中标记完成。用户也可以点击计划日历右上角的“…”直接添加自定义日程，设置起始日期、终止日期和事件描述；勾选“硬截止”会在终止日标红点、在事项卡左侧标注。自定义事项可在卡片右侧点“删除”，再点“确认删除”。“我的”保存原始输入和可编辑的用户资料，后续问答自动带入。没有提醒通知、跨设备同步、代办、具体房源推荐。

初次使用时会先收集公司位置、入职时间和计划完成搬家的时间，再生成待确认的首版计划。模型回答中的每项建议会单独展示依据状态，未知或待核验的信息有醒目标记。日程修改确认表只展示本次新增、修改和删除的事项；提醒时间请到“我的”页面自行调整，不生成计划清单变更。

## 本地运行

需要 Python 3.10+。**试界面和区域数据**：在终端运行 `zsh 试用演示.command`，再打开 <http://127.0.0.1:8765>。此模式只用固定规则生成演示回答，**没有调用大模型，也不会产生 AI 日程提议**。

**试真正的 GPT 聊天和日历（不需要微信 AppID）**：在 [OpenAI Platform](https://platform.openai.com/api-keys) 创建 API 密钥；把 `.env.local.example` 复制为 `.env.local`，仅在本机填入 `OPENAI_API_KEY`。先运行 `zsh 启动GPT试用.command`，**保持这个终端窗口开着**，再打开 <http://127.0.0.1:8766>；只打开网址不会自动启动服务。默认模型为 `gpt-5.6-luna`，可在配置文件中修改。演示服务和 GPT 服务使用不同端口，可以同时开着。

在“助手问答”中输入“我 2026 年 10 月 15 日在张江高科入职，想在 10 月 12 日前租好房、14 日搬入，请给我计划表”。回答下方会出现“日程修改确认表”，列出修改后的完整日程和本次变更。可以继续说“把看房签约改到 10 月 11 日”，确认表会重新生成；点击“需要，更新计划日历”才会生效，点击“不需要改动当前日程表”则保持原日历。切换“计划日历”可按月份和日期查看，并标记任务完成。

新用户也可先完成问答页的两步引导，输入办公位置、入职时间和计划完成搬家时间，再生成首版计划。一次性预算、月租预算、通勤、合租和住房偏好可稍后在“我的”补填。确认后的未完成日程会在问答页展示最优先的 1–3 项。

“我的”会展示聊天中明确提供的城市、公司位置、入职时间、通勤、租房和搬家预算等信息；可以直接修改并保存。每次输入的原文保留在“历史输入”中，刷新页面后仍可查看。已保存资料会进入后续模型问答和区域数据筛选；只有最近 24 条对话进入单次模型请求。可以点击“清空我的资料和聊天记录”删除这两类记录，计划日历不会受影响。启用此功能前的旧聊天没有保存，无法自动找回。

若要接其他兼容 Chat Completions 的模型服务，也可沿用原来的三项 `LLM_*` 环境变量，然后运行；目前该兼容路径只支持问答，不生成结构化日历提议：

```bash
python3 backend/server.py
```

浏览器打开 <http://127.0.0.1:8765> 即可试聊；`curl http://127.0.0.1:8765/health` 可检查配置。未配置模型且未开启演示模式时，接口会返回明确错误，不会伪造 AI 回答。若要在微信小程序里试，需安装微信开发者工具并导入本目录；`project.config.json` 中的 `touristappid` 要替换成你自己的测试 AppID。开发者工具本机调试可使用当前 HTTP 地址；真机测试与发布时需把 `API_BASE` 改为已配置的小程序合法 HTTPS 请求域名，并在服务端部署此后端。

`AppID` 是微信小程序 ID，不是 OpenAI 密钥。浏览器试 GPT 完全不需要它。已有小程序账号时，在[微信公众平台](https://mp.weixin.qq.com/)的小程序后台进入“开发与服务 → 开发管理 → 开发设置”查看；还没有账号时，先在公众平台注册小程序账号。不要把微信 AppSecret 写进前端。

## 数据口径

- 新增 `data/shanghai_knowledge.json`：附件 v1.1 原始快照（59 条知识：31 verified / 26 pending_verification / 2 sample_reference；41 个入口、12 个模板、2 条费用补缺、35 条缺口、58 条来源）。已核对 ZIP 内 SQLite 六表数量一致；运行时只读 JSON，不需要导入数据库或安装依赖。
- 模型每次问答通过 `context_for` 按用户消息及资料选取相关主题，附带入口、模板、费用缺口和未解决缺口；这是请求时提供知识上下文，并非训练模型。更新 JSON 后须重启后端。演示模式仍为固定规则，不代表真实模型使用新知识的效果。
- 接入层保留附件的原始状态为 `imported_status`，缺可追溯来源的条目降为待核验；入口缺 URL、名称、核验时间或 fallback 也不会标为已核验。5 条热线已补充政府页面来源，电力使用 95598，公积金热线规则使用 12329。来源见 `backend/knowledge.py`。
- 附件 3 条搬家/二手知识缺 evidence，其中 2 条 verified 在接入层降为待核验，另 1 条继续保留样本状态；3 条入口字段不完整，暂作待核验。模板租房引用已按第二轮知识补齐。已解决缺口不再注入旧描述，但不会据此升级仍待核验的政策条目。租房公积金额度/承诺制仅用于核验任务；燃气旧价统一作为待核验，移动/联通无可确认报价；体检只向 HR 核验，落户不作资格承诺。导入不意味着重新逐页核验了全部来源。

- `data/shanghai_area_data.json` 是唯一的区域数据主版本，来自用户提供的 2026-09-22 快照。
- 租金是挂牌抽样参考，不是统计租金或实时可租房源；通勤为线网估算，只有陆家嘴、张江高科、徐家汇三处办公枢纽；配套地点均未逐条核验。
- `backend/knowledge.py` 收录经官方页面核验的核心政策事实、来源及非政策性质的办事建议；其他政策问题必须明确不确定性，不能由模型自行推断资格。用户提供的 HTML 知识库用于提炼流程，但原文中的未核验条目没有直接作为确定政策输入。
- 网页资料、全部历史输入、最近 40 条对话及日程存在当前浏览器的本地存储中，不会跨浏览器或设备同步。后端不落库，但每次请求会将已保存的资料、最近 24 条对话和日程状态发给所配置的模型服务。清理浏览器站点数据会删除本地记录。演示模式只保存原始输入，不能自动提取结构化资料；“我的”仍可手动填写。上线前需完成隐私告知、服务协议、域名配置及部署安全检查。
